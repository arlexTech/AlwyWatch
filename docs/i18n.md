# Languages

Every app (Android phone/TV, desktop, web) and the core share one set of translation files:
`i18n/<code>.po`, one per language, in the standard gettext format that tools like
[Poedit](https://poedit.net) and Weblate open directly. The English text in the code is the
key: there is no `en.po`, and anything not translated yet shows in English.

## Adding a language

1. Start the file, with the language's code, its own name and its plural rule (copy the
   `Plural-Forms` line for your language from the
   [gettext plural table](https://www.gnu.org/software/gettext/manual/html_node/Plural-forms.html)
   or from any open source project's `.po`):

   ```sh
   scripts/i18n.py new de Deutsch "nplurals=2; plural=(n != 1);"
   ```

2. Translate `i18n/de.po` (Poedit, Weblate, or a text editor). Keep every `{name}` exactly as
   it is, and read [Rules for translators](#rules-for-translators).
3. `scripts/i18n.py check` tells you how complete it is and catches broken placeholders.
4. Build. The language appears in Settings → Language & about on every app, in Android's own
   per-app language setting, and is picked automatically for people whose device or browser
   is set to it.

Nothing else changes: no code, no list of languages to edit.

## Rules for translators

* `{days}`, `{name}`, `{n}`, `{}`, `{0}` are filled in by the app: keep them, move them where
  your grammar needs them, never translate the word inside. In a plural entry the singular
  form may leave `{n}` out ("un titre"), nothing else may be dropped.
* `HTTP {status}` stays as is (the apps read the number back).
* Keep it short: much of this text sits on buttons, TV menus and poster badges.
* Names stay as they are: AlwyWatch, Jellyfin, Plex, Seerr, Overseerr, Jellyseerr,
  Maintainerr, Tautulli, Pocket ID, Quick Connect (Jellyfin's own feature name).
* A line marked `#, fuzzy` is not used until you remove the mark.

## For developers

Every text a person reads goes through the translation functions; logs, setting keys,
identifiers, URLs and messages to servers do not.

| Where | Plain | With values | Plural |
|---|---|---|---|
| Kotlin (`be.alwyapps.watch.ui.tr`) | `tr("Sign in")` | `tr("Leaves in {days} days", "days" to d)` | `trn("{n} title", "{n} titles", count)` |
| Rust (core, desktop, web) | `tr!("Sign in")` | `tr!("Leaves in {days} days", days = d)` | `trn!("{n} title", "{n} titles", count)` |
| Slint | `@tr("Sign in")` | `@tr("Leaves in {} days", d)` | `@tr("{n} title" \| "{n} titles" % count)` |

* Whole sentences, never pieces glued together: word order differs between languages.
  `tr("Signed in as {name} on {server}", …)`, not `tr("Signed in as") + " " + name`.
* One literal per call (the extractor reads the code): no `+`, no `$name` templates in Kotlin,
  no `format!` inside `tr!`.
* Translate where the text is shown, not in constants, enums or statics: those are built once,
  before or regardless of the selected language.
* Text that belongs to the media server (titles, overviews, genre names) is not ours: shown
  as it comes.

After adding or changing text, run `scripts/i18n.py extract`: it updates
`i18n/alwywatch.pot` (the template, generated) and adds the new texts to every `.po`,
untranslated. CI runs `scripts/i18n.py check`, which fails when the template is out of date or
a translation breaks a placeholder.

How it fits together: the `i18n` crate (`core/i18n`) compiles the `.po` files into tables at
build time (nothing parsed or loaded at run time). Rust code uses it directly; Android gets the
selected language's table from the core once, before the first frame; the desktop build
also bundles the same files into the Slint UI (`desktop/build.rs`).
